# 검증 결과 영수증 PoC

2026 모바일신분증 아이디어 공모전 제출용 개념 검증(PoC)입니다.
**가상 데이터·데모용**이며 실제 행안부 시스템과 연결되어 있지 않습니다.

## 목적

매장·기관은 신분증 화면이나 사진을 보는 대신, **발급기관 서명으로 검증된 결과**(예: 만 19세 이상 Y/N)만 받습니다.
검증할 때마다 매장 키로 서명한 **영수증**을 보관하며, 영수증에는 개인정보가 없습니다.

| 영수증 필드 | 내용 |
|---|---|
| `result` | Y / N |
| `claim`, `purpose` | 확인 항목(`age_over_19`), 목적(주류 판매 연령 확인) |
| `store` | 매장 ID (헤더의 매장 인증서 `scert`로 등록기관 서명과 연결) |
| `iat`, `exp` | 검증 시각, 파기 예정(90일) |
| `vp_hash` | 제시물 SHA-256. 제시물마다 nonce가 새로 들어가므로 같은 사람의 영수증끼리 연결되지 않음 |
| `ver`, `rid` | 형식 버전, 무작위 영수증 번호 |

이름, 생년월일, 주민등록번호, 사진, 지갑 키는 들어가지 않습니다. 허용 목록 밖의 필드가 있거나 값이 생년월일·주민등록번호·전화번호 형태이면 분쟁 검증에서 실패로 처리합니다.

## 실행

```bash
cd poc-검증결과영수증
python3 -m http.server 8000        # 또는 python3 scripts/serve.py 8000
# 브라우저에서 http://localhost:8000/
```

- 빌드 도구가 없습니다. 정적 파일(HTML/CSS/ES 모듈)만 있습니다.
- WebCrypto와 카메라는 **localhost 또는 https**에서만 동작합니다. `file://`로 열면 ES 모듈이 막힙니다.
- macOS 기본 Python 3.9의 `http.server`는 대기열이 작아, 모듈 여러 개를 동시에 받을 때 가끔 `ERR_CONNECTION_RESET`이 납니다. 화면이 비면 새로고침하거나 `scripts/serve.py`(표준 라이브러리, 대기열 128)를 쓰세요.
- 휴대폰 두 대로 시연하려면 https가 필요합니다(카메라 권한). 예: 같은 폴더를 GitHub Pages에 올리거나 `npx http-server -S` 등. 발급기관 키가 코드에 고정되어 있어 서로 다른 기기끼리도 검증됩니다.
- QR 생성·인식 라이브러리는 CDN에서 받습니다. 오프라인이면 QR 대신 텍스트 붙여넣기로 같은 흐름을 진행할 수 있습니다.

## 테스트

```bash
node --test test/*.test.mjs   # Node 20 이상, 외부 패키지 없음 (내장 webcrypto)
```

검사 항목(22개): 발급(만 나이, salt 해시, 평문 미포함), 제시(만 19세 이상 하나만 공개), 검증과 영수증(Y/N, 개인정보 없음, 비연결성, 다른 매장 거부), 변조(생년 변조, 서명 위조, 재사용 nonce, 다른 검증기 nonce, nonce 만료, 탈취 재서명, 형식 불량), 영수증 위변조·만료(90일, 결과 변조, 미등록 매장, 개인정보 필드), 봉인 사본(기한·수신기관·철회, 기한 연장 변조), 측정(CSV·요약).

  demo-keys.js      가상 발급기관·가상 검증앱 등록기관 고정 키 (공개된 데모 키)
  sdjwt.js          SD-JWT 유사 자격증명 발급·제시(KB-JWT)·검증
  verifier.js       1회용 nonce 저장소, 검증 요청, 검증+영수증 발급
  receipt.js        매장 인증서, 영수증 발급·검증(형식·서명·필드·90일)

  sealed.js         확장: 목적·기한 봉인 사본
  measure.js        단계 수, 시간 기록, CSV

### 신뢰 구조

```
가상 발급기관 키 ──서명──> 자격증명(_sd 해시 목록 + 지갑 공개키 cnf)
지갑 키 ──서명──> KB-JWT(aud=매장, nonce, sd_hash)          → 제시물(VP)
가상 등록기관 키 ──서명──> 매장 인증서(매장 ID, 매장 공개키)
매장 키 ──서명──> 영수증(결과, 시각, 매장, 목적, 만료, vp_hash) + 헤더에 매장 인증서
```

검증기 검사 순서: 형식 → 발급기관 서명 → 유효기간 → 선택공개 해시 → 홀더 키 바인딩(서명·sd_hash) → 수신자 → nonce(발행 여부·미사용·120초) → 제시 시각(±300초) → 요청 항목.
요청하지 않은 항목이 들어오면 표시·보관하지 않고 버립니다. 실패한 제시물에는 영수증을 발급하지 않습니다.

## 화면

| 탭 | 내용 |
|---|---|
| 발급기관 | 테스트 신원(이름, 생년월일) → 항목별 salt 해시 + 발급기관 서명 자격증명 발급 |
| 지갑 | 자격증명 보관, 검증 요청 수신(스캔/붙여넣기/같은 기기) → 「만 19세 이상」만 공개한 제시물 QR, 제출 내역 |
| 검증(매장) | 1회용 요청 QR → 제시물 스캔(카메라/이미지/붙여넣기) → Y/N만 표시 → 영수증 보관, 건수 통계 |
| 분쟁 검증 | 영수증 붙여넣기 → 매장 인증서·매장 서명·필드·90일 검사, 필드 전체 표시, 91일 후 시점·결과 변조 시연 |
| 위조 시연 | 생년월일을 고친 캡처 이미지(이미지 속 QR을 실제로 읽어 검증), 변조 4종(생년 변조, 서명 위조, 재사용 nonce, 탈취) |
| 측정 | 기존 5단계 대 2단계 표, 검증 단계별 ms 기록, 30회 벤치마크, CSV 내보내기 |
| 확장: 봉인 사본 | 받는 기관·목적·기한을 홀더 서명에 묶은 사본 → 기한 후·다른 기관·철회 시 무효 |

## 실제 시스템과의 차이

- **가상 키**: 발급기관·등록기관 키는 코드에 개인키까지 공개된 데모 키입니다. 실제로는 HSM에 있고 공개키만 배포됩니다.
- **행안부 API 미연동**: 모바일신분증 발급, 검증앱, 등록기관 기능을 모두 브라우저 안에서 흉내 냅니다. 실제 모바일신분증의 데이터 형식·프로토콜(OmniOne Open DID 등)과는 다릅니다.
- **SD-JWT 단순화**: IETF SD-JWT VC 구조(salt 공개값, `_sd`, `cnf`, KB-JWT, `sd_hash`)를 따르되 디코이 해시, 배열 요소 공개, 상태 목록(폐지 확인)은 생략했습니다.
- **연령 항목**: `age_over_19`는 발급 시점 값입니다. 실제로는 짧은 유효기간 재발급이나 검증 시점 계산이 필요합니다.
- **저장소**: 지갑·매장 데이터는 브라우저 localStorage에 있습니다. 실제 영수증 보관·90일 파기·통계 집계는 서버 또는 검증앱 저장소의 일입니다.
- **영수증 발급 위치**: 공모전 조건(민간앱 연계·활용 제한)에 맞춰 영수증은 행안부 검증앱 안에서만 발급된다는 전제입니다. 데모에서는 한 페이지의 「검증(매장)」 탭이 그 역할입니다.
- **철회**: 봉인 사본 철회는 같은 브라우저의 철회 목록으로만 반영됩니다. 실제로는 상태 목록 조회가 필요합니다.

## 측정 방법

- 검증기의 `verifyPresentation`이 단계마다 `performance.now()` 차이를 기록합니다: 형식 해석, 발급기관 서명, 선택공개 해시, 홀더 서명, nonce·시각, 영수증 서명(`issueReceipt`), 합계.
- 「측정」 탭의 「정상 검증 30회 실행」은 요청 생성 → 제시물 생성 → 검증+영수증을 30회 반복하고, 검증기 쪽 시간만 기록합니다. 직접 검증·위조 시연도 같은 표에 쌓입니다.
- CSV 열: `time, scenario, outcome, failed_check, parse_ms, issuer_sig_ms, disclosure_ms, holder_binding_ms, nonce_ms, receipt_ms, total_ms, user_agent` (엑셀용 BOM 포함).
- 포함하지 않는 것: QR 인식 시간, 사람이 화면을 보는 시간, 기존 방식(육안 확인·CCTV 검색)의 실제 소요 시간. 기존 방식은 단계 수로만 비교합니다(5단계 → 2단계).
- 참고 측정(2026-10-19, macOS, headless Chrome): 성공 검증 32건, 영수증 서명 포함 합계 중앙값 0.4 ms, p95 0.6 ms. 실제 시연 기기(휴대폰)에서 다시 재서 제출하세요.
